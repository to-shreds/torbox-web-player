# Host-backed watch parties

The host now supplies the TorBox connection for both viewers. A guest opens the invitation or pastes its code and joins without entering an API key or signing into TorBox. Separate links are requested for each device, and video continues directly from TorBox to the browser.

TorBox CDN links can contain the full host API key, as this project's prior real-account tests established. Before creating each party, the host must acknowledge that the invited person could extract that key and use the TorBox account outside the app. This choice is never remembered. Ending the party ends further app access, but revoking a copied key requires resetting it in TorBox. Old clients without explicit consent still require a key-free provider link and fail closed if it is unavailable.

The guest app is restricted to one room and its exact file. It cannot browse the host's library, search other titles, create a party, transfer a setup or use owner functions. Room membership, host login, host playback proof and exact media identity are checked during preparation, playback and media handoff. A host departure or video change ends the room. No relay fallback, service plan change or separate application package is added.

Existing guests can reload and restore the party. A guest who has a separate TorBox setup retains the original session, encrypted key, settings, source memory and resume history when leaving. Kid Mode continues to require the Parent PIN before joining or restoring a party. Shared play, pause, seek, buffering holds and drift correction remain.
