# Watch parties

Start a movie or episode, choose **Watch party**, then **Create party for this video**. Copy the invitation and send it to one other person. They connect their own TorBox account, open **Watch party**, paste the invitation and choose **Join party**. Opening an invitation link fills the code automatically after sign-in.

Joining loads the exact same torrent, relative file path and byte size through the second viewer's own account. The player will not silently choose another cut or episode. Only already-cached content can be added during joining. A third viewer cannot enter an occupied two-person room.

Choose **Play together** once both players are ready. If the browser asks, tap **Ready to watch** on that device. Either viewer can use the party buttons or normal video controls to play, pause and seek. **Sync now** aligns the local player with the shared position. A two-second coordinated start and ongoing clock/drift correction keep the videos aligned. Playback runs at 1×; small temporary speed corrections avoid repeated visible seeks. This is synchronized browser playback, not a promise of frame-perfect timing on every network and device.

Buffering, an autoplay block or a hidden non-PiP page pauses the party. A lost connection is detected within approximately 10–11 seconds; the affected device also stops when its synchronization request fails. Both players must be ready and aligned before a coordinated restart. A stale guest slot can be reclaimed after its presence timeout by someone with the invitation. Closing the player, changing viewer, entering Kid Mode, signing out, leaving Movies or changing files leaves the party. The host leaving ends the room. Auto-next and source switching are held while the party pins the current video; start a new party for another episode or source.

Parties support the site's movie/episode player. Sports pages and external provider players are not synchronized by this feature. Both viewers need their own TorBox connection; temporary title-only guest sessions cannot create or join parties. Each person streams directly from TorBox to their own device. No host API key, media URL or playback ticket is sent to the other viewer, and no video bytes pass through Render.

The existing free Render service stores at most 100 in-memory rooms. Invitations are random 256-bit capabilities, hashed at rest, expire after six hours and require an authenticated member session. Rooms have exactly two members, no public listing and no chat. Server restarts/deployments end rooms; reload or renewed login can require a new invitation. No database, paid service or third-party synchronization account is added.

The authenticated POST endpoints under `/api/watch-party/` implement `create`, `join`, `prepare`, `sync` and `leave`. Messages are limited to 8 KiB. Per-session limits separate small heartbeats from provider/source operations. A server-issued playback proof binds synchronization to the last stream issued to that viewer; new playback invalidates the old proof. Each command has an increasing member sequence number so a lost response can be retried without replaying an old control. Provider identity is checked again during exact-file preparation. Source metadata never supplies arbitrary playback URLs.

Tests use independent browser sessions and TorBox provider instances with different account-local torrent IDs, the same verified file identity, and a locally generated original MP4. They verify real decoded video timing, native and party controls, wrong-cut rejection, readiness, buffering, offline recovery, autoplay, per-viewer lifecycle and zero media-relay bytes. Fixture timing does not establish live Internet or physical-device timing.
