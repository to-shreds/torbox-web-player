# Sports feature report

Build: release-1.2.0-sports.1. Native counterpart: TorBox TV 0.2.0, independently compiled and released.

## Behavior

Sports opens before private-service startup/login. The four bundled live channels are T2 tennis, Red Bull TV, Pickleball TV and NHL classics/coverage. The archive includes sixteen full 2026 Premier Padel sessions from Paris, Malaga, Bordeaux and Valladolid. It is a release snapshot, not an automatically maintained event guide. It does not promise all premium sports or a complete tennis archive.

Live/replay tabs, sport filters and search expose event/round/date only. No scores, result descriptions or result-bearing images are rendered. Sports requires an adult viewer, avoiding a new route around Kid Mode allowances. Replays have separate local bookmarks and Start Over; live has Go Live and never applies a replay bookmark. Closing cancels obsolete resolutions and releases HLS. Failure/start/buffering deadlines expose Retry and channel choices. HLS prefers at most 720p, with 480p/1080p/Auto choices; native browser HLS fallback uses its own adaptive quality.

## Sources and separation

The current public Red Bull player API supplies replay links for public resource IDs with no account, application secret or session token. Requests omit credentials, reject API redirects and respect playability errors. Playlists/segments stay on an exact verified HTTPS sports-host allowlist, distinct from TorBox's media/key policies. Sports uses no iframe, subscription, VPN, TorBox login or Render video relay. Regional availability and provider schedules remain outside the app's control.

The Apache-licensed hls.js 1.6.15 distribution is bundled locally with public/HLS-LICENSE.txt; script policy remains self-only. MediaSource playback adds blob media permission. The HTML shell's connection policy includes only exact sports API/CDNs plus the existing private backend. Private JSON API responses retain their preceding local-only CSP. Sports files are included in the scope-specific shell cache; remote media/API calls are never cached by that worker. Movie credentials, history/settings formats and matching/source rules are preserved.
