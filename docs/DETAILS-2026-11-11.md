## Behavior

- **Readable descriptions.** Removed the synopsis's two-line CSS clamp. The
  supplied description now wraps normally, and the dialog scrolls vertically.
  Long headings and the My list control wrap within narrow screens.
- **Watch trailer.** Movie details include a YouTube link. A validated trailer
  ID supplied by Cinemeta opens that trailer; otherwise the link searches
  YouTube for the title, year, and official trailer. Opening the link preserves
  the player's current page. Trailer availability and language depend on the
  provider; a title with no listed trailer is not presented as having a verified
  direct trailer. There is no embedded or automatically loaded YouTube player.
- **More like this.** A shelf below the title's actions or episodes shows up to
  12 movies or shows of the same type, ranked by actual genre overlap and shared
  directors/cast when available. The selected title, duplicates, wrong media
  types, and unrelated feed entries are excluded. These are genre-based
  suggestions, not a personalized recommendation service.
- **Ratings.** IMDb ratings retain their own label. Rotten Tomatoes percentages
  come from a source explicitly identifying Rotten Tomatoes, never from an
  IMDb conversion or an inferred score. Without an API key, the app uses
  verified, dated Tomatometer records from Wikidata and displays their recorded
  date and source. These are snapshots and may differ from today's score. An
  optional OMDb key in Settings enables OMDb ratings; missing OMDb results can
  fall back to a dated Wikidata record. Missing or unverifiable scores stay
  absent, with a Rotten Tomatoes lookup link available in ordinary details.
  Browsing cards reuse scores already cached from opened titles.

Guest details do not expose the new enrichment controls. Kid Mode omits
trailers, external rating links, and the similar-title shelf. Existing playback
allowances, title identity checks, audio recovery, source selection, resume,
watch parties, Games, Sports, saved history, and TorBox credentials are retained.
The separate native Fire Stick APK is outside this update.

## Performance and request boundaries

Trailer IDs and IMDb ratings travel in the existing Cinemeta metadata response.
They add no separate startup request. Play and source preparation do not wait
for ratings or suggestions.

The similar shelf loads when it approaches the visible part of the dialog.
The backend shares the existing five-minute metadata/browse cache and makes
at most two optional genre-feed reads, each with a six-second request budget.
It does not fetch details for every suggested title or fan out through backup
feeds. Results are cached in the browser for five minutes. Partial feed success
remains usable; complete failure provides a retry control.

Ratings start after the main details render. Both providers have bounded
requests, limited concurrency, and caches of at most 200 title records. Positive
ratings are cached for seven days; missing results expire sooner. The main grid
does not make one ratings request per poster. Closing, changing, or remounting
details cancels its outstanding enrichment work, and obsolete responses cannot
update a new title. Settings changes refresh existing poster badges.

Rating requests contain public title identity. The optional OMDb key stays in
this browser and is sent only to OMDb; it is separate from the TorBox key and
settings-transfer data. The HTML CSP permits only the two exact new ratings
origins alongside the existing connection allowlist. Scripts remain self-only.
The new modules are registered in the backend's public asset allowlist and the
service-worker cache. Root and `/key/` publication use the same frontend source.
